# One Page BI V0.7.0 Windows 版

[English](README.md) · 简体中文

**本项目采用 vibe coding 的方式，与 AI 协同制作完成。整体设计与结构搭建由我本人完成，AI 协助代码实现、问题排查和测试验证。**

我做 One Page BI，最初的想法很简单。很多小企业并不缺数据，桌面上到处都是 Excel、销售明细和收支记录。真正麻烦的是，每次想看清生意怎么样，都要重新找文件、整理表格、核对数字，再花时间做一份能看懂的报表。

我希望，这件事能像在游戏里使用合成台一样自然。把手头的材料放上去，软件告诉你能做什么，选一个，就能得到一页清楚的结果。文件像物品一样放进背包，做过的报表随时可以找回来。用户不用先理解一大堆专业术语，也能知道下一步该怎么做。

我理解的“大道至简”，是把复杂的事情认真做好，再把简单的用法留给用户。界面上的每一句话、每一个按钮，都应该让人少想一步。报表里的图表应该帮助人看见变化、差距和问题，让数据自己说话。数据不够、含义不清楚时，软件也应该明确告诉用户，算得出的数字要经得起核对。

它可以是桌边一个随手打开的小窗口，帮人快速回答今天的问题。需要深入时，也能继续查看原始数据、检查整理过程，把结果带进更专业的分析工具。我希望它用起来轻巧，做起事来可靠，让普通人也能把自己的数据真正用起来。

[下载 Windows x64 版](https://github.com/timschendot-commits/one-page-bi/releases/download/v0.7.0/OnePageBI-V0.7.0-Windows-x64.zip)，解压后双击 **OnePageBI.exe**。

把手头的表拖进九宫格，就能看到这些材料可以生成哪些报表。左边的模板可以先不选。软件默认英文，右上角的 **中文 / English** 可随时切换，并记住你的选择。

## 看成品与继续编辑

在背包的“示例文件夹”中加入销售明细，选择销售分析并生成。成品区直接显示 CNY 3,393.00 销售额、10 笔订单、339.30 平均订单额、月度走势和品类排名。指标读取当前报表的实际数据；缺失的订单号不会产生估算订单数。单月只显示实际值，不跨缺失月份连线。点“整页查看”可以放大；“保存到桌面”写出独立报表，“取消选择”保留工作台上的材料。

- **收藏及搜索**。报表目录中的 ☆ 可收藏。打开目录时先显示收藏，再显示常用，其余按销售、账务、采购库存、项目成本分类。可以搜“客户还没付款”“库存压了多少钱”或“unpaid bills”。搜索用离线词表及相关度排序，只从已有配方中返回结果。常用排序依据本机成功生成记录。新增客户集中度、供应商集中度和库存账面价值。
- **窗口**。拖 One Page BI 标志移动，拖边缘或角调整大小。在右上角 ◐ 里选松绿、海蓝、梅紫，或进入“悬浮小窗”。小窗可在材料、报表、背包间切换，可选置顶。选“收起到托盘”后双击 Windows 通知区图标恢复；右键图标可以切换小窗、大窗或退出。右上角 × 会退出软件。
- **Power BI 与 Word**。生成后或在历史记录选“专业编辑”。首次打开会从校验过的报表创建可编辑副本。打开 `Workbench.pbip`，在 Power BI Desktop 第一次点“刷新”，即可加载内嵌的本地快照。项目包含原生可视化和 Facts 明细表。销售、订单的核心指标使用 DAX；其他配方提供本次生成的指标和图表快照，进一步做跨表筛选时可基于明细添加关系和度量值。默认模型未连接企业实时数据源。DOCX 的标题、指标、分类和数值表均可直接编辑。
- **保存版本**。编辑文件保存在文档目录 `One Page BI/Editions/<归档编号>/Working`。下次从同一历史记录进入会复用它。先在外部编辑器保存，返回后点“归档已保存的修改”，会在 `Revisions` 生成独立 ZIP。也可直接“导出可编辑文件包”到自选位置。ZIP 含业务数据、PBIP 工程和 DOCX；把整个 ZIP 解压到同一目录后使用。初始归档保留原始凭据。V0.5 之前未带校验清单的归档仍可按原方式打开。

## 先体验补货报表

打开背包的示例文件夹，点 **Reorder-check.psv**，右侧选 **哪些货该补，补多少？**，再点 **生成并归档**。示例的北库缺 9 件、南库缺 6 件，到达最低线的库存项不触发，本次建议共补 **15 件**。要检查某个数字，点“查看采用的列”，可同时看到原表列名和例子。

V0.6 修复了中文界面查看部分业务报表口径时的白屏。报表目录可以按“欠我”“库存”“复购”等词搜索。选择的模板缺材料时会显示缺少哪些列，并可直接点对应文件修改。系统在你选择报表后逐行检查，校验通过即可生成；也可点“先看预览”。

新增补货建议、复购客户、在谈商机。补货使用明确提供的预计可用量、最低库存和目标库存。复购按筛选范围内净额为正的不同订单统计；正好两条商品行仍可能只是同一个订单。在谈商机按快照逐单计算金额 × 来源表百分比，四舍五入到分后合计。同快照每个商机须唯一且明确为在谈。示例 **Open-deals.jsonl** 的两笔在谈金额为 MYR 3,234.50，加权后为 MYR 1,993.80。

可以拖入扁平 **.jsonl / .ndjson**、**.psv** 和含 Excel `sep=;` 等首行分隔符声明的文件。JSON Lines 每行一个对象，按键名对齐；重复键、嵌套对象和数组会提示来源行。金额写成 `1.234,50` 时，在该材料的用途设置里明确勾选“小数逗号”。只有已映射的数值列会转换，原始编号与整理快照保留。该选项随本次归档保存和复算。

## 工作台与材料

直接拖入一份表，点亮的材料格可以查看 SQL 整理后的字段和样例。UTF-8 和带 BOM 的 UTF-16 文本可使用逗号、分号、制表符或竖线。程序按内容判断，文件名可以是编号。无表头时保留第一行，用编号指代原列。遇到含义不明的金额，请手动选择材料用途、核对字段并确认。表头位置和“无表头”选项均可调整。

“报表目录”提供 **27 种可运行报表**，其中有客户、商品、门店和渠道销售，供应商采购、费用、毛利、库存快照、应收与应付账龄、项目开票、工单成本、科目借贷发生额、试算平衡勾稽、期间收入费用、资产负债平衡核查和预算对比。专业报表依赖明确的科目分类、期间、币种和金额口径。查看[行业适用范围、来源与核验方法](REPORT-RULES.md)。

推荐先试示例背包里的 **x17.csv**。它是 UCI 真实交易数据的前 32 行，列顺序倒置，使用分号和 UTF-16，首行是说明。选销售分析并指定 GBP，数量乘单价合计为 **819.55 英镑**。这是该片段的商品行金额，原始数据不足以证明税后收入或整单退款分摊。**17-B.csv** 是合成的试算平衡例子，**Q9.csv** 是应付发票例子，**NO-HEAD.csv** 用于体验无表头导入。

每次放入文件时都会生成会话临时材料；正常退出时会清理该会话的临时文件。合成后，“历史记录 → 核查材料与重新验证”可以切换完整整理表与报表采用的字段，翻页查看，另存 CSV，或从归档原件重新运行并比较。旧版本的报告仍可打开，V0.5 之前没有可用于此功能的材料和校验清单。校验可发现相对于归档清单的变化，并不能证明企业交来的原始数字真实。CSV 另存会防护可能被表格软件当作公式的文本；在 Excel 中请以文本导入有前导零的编号。

## 启动并做出第一份报表

1. 解压 **OnePageBI-V0.7.0-Windows-x64.zip**，运行 **OnePageBI.exe**。保留同目录的 DLL、`ui`、`licenses` 和 `examples`。需要 Windows x64、.NET Framework 4.8 及 [WebView2 运行时](https://developer.microsoft.com/microsoft-edge/webview2/)。
2. 背包默认打开桌面。切到中文后，在背包位置菜单选 **示例文件夹**。按住 Ctrl 选中“订单主表_演示.csv”和“订单行_演示.tsv”，还可以同时选中平台结算单、银行流水。将选择的文件一起拖到九宫格。也可以从资源管理器拖入、点空格子多选文件，或点背包里的数据文件。
3. 右侧会列出匹配的报表。选 **订单分析**，核对哪份表提供订单日期、哪份表提供商品金额，核对币种 MYR 后选择“先看预览”。两份订单材料会高亮，其余材料变灰，仍可留作下一份报表。
4. 点箭头右边的成品格合成。这个演示应得到 **销售额 MYR 125.00、2 笔订单、平均每单 MYR 62.50**。打开独立报表可筛选、导出 PNG。把成品拖回背包，或点“放入背包”，桌面会出现可离线打开的 HTML。切换组合后可以继续用其他材料。

## 实际能用哪些材料

| 想回答的问题 | 可用材料和条件 |
| --- | --- |
| 卖了多少钱？ | 一张明细有日期和每行最终销售金额即可，有退货时按实际正负号计算。只有数量和单价时，支持整数数量 × 非负单价，再减明确的行级折扣金额。没有可靠的订单号仍能算销售额，订单数和客单价留空。 |
| 有几笔订单，平均每单多少？ | 一张表可以同时带订单号、日期和金额，也可以分别来自订单主表与商品行表。后者要求主表一单一行、两边完整订单号集合一致。一个订单可有多条商品行。前导零有意义时请用文本保存订单号。 |
| 几期销售能一起看吗？ | 可合并 2–9 份日期不重叠、币种一致的销售期间。需要确认属于同一业务、销售口径相同。存在重叠的其他来源时，可选其中兼容的两份。跨期重复的订单号会阻止生成。 |
| 钱实际收进来、付出去多少？ | 已入账日期配带正负号的收支额，或分别映射借方与贷方；同一行不能两侧都有非零值。可看收入、支出及净变动。银行入账额不能直接推出销售额。 |
| 平台结算是否到账？ | 配对平台净打款和银行流水。仅当参考码唯一且完全一致、同币种金额精确到分、银行正向到账在结算后 0–7 天内时自动确认。重复、冲销、差额、日期异常和未关联流水留待核对。明细可追到来源行，筛选出的异常可导出 CSV。 |

字段映射是解释列含义的步骤，不占材料格。“日期、金额”不足以区分销售与收付款，需要使用者确认。匹配列表区分“已检查数据行”“核对含义”和需要修正的组合，最终合成前会逐行验证。订单数按当前筛选范围内的唯一订单号计算，客单价为筛选后的净销售额除以订单数。

## 表头、材料和限制

- 点已放入的材料，可以换工作表、指定第 1–50 行作为表头、选择业务含义并手动映射原列名。映射时会显示样例值。一份工作簿的不同工作表也可以配合使用。自动检查前六张可见表，其余可手动选入。
- 接受可识别分隔符的 CSV、TSV、XLSX，以及含可复用数据的 `.onepagebi.html`。将成品报表拖入时只读取嵌入数据，从背包点报表则会在浏览器打开。
- 九宫格最多放九份文件，内容完全相同的副本只算一份。单份数据文件上限 5 MiB，成品 HTML 上限 16 MiB。每张表最多 10,000 行数据、80 列；XLSX 解压上限 32 MiB、2,000 项。请保留唯一且非空的表头，移除合计、余额与页脚，公式转为值。日期支持年-月-日、年/月/日及兼容的 Excel 日期。日/月/年格式需要手动勾选。
- 涉及单独计税、运费、百分比折扣或无法确认的退款分摊时，请提供实际行净额。当前支持订单主表关联、分期合并及结算核对这几类组合，不做任意表间关联、币种换算、截图/PDF 取数、预测或直接生成 PBIX 二进制文件。

例如 Shopify 的订单导出会把同一单的商品拆成多行，退款金额可以属于整单。遇到这类表，请提供每行实际净额，或整理为每单一行的已核实净额。软件会阻止重复累加整单金额，也会阻止在退款尚未分摊时推算净额。[Shopify 订单导出字段说明](https://help.shopify.com/en/manual/fulfillment/managing-orders/exporting-orders)

## 历史、桌面成品与数据保存

每次成功合成都在 Windows 文档目录的 `One Page BI/Reports/<id>/` 创建独立归档。“历史记录”可打开报告、导出原始 PNG 或打开归档文件夹。归档仅包含参与该组合的原始文件快照（`inputs/`）、验证后的数据（`data/processed.json`）、独立交互报表（`dashboard/report.html`）、1800 × 1134 的汇总 PNG、模板配置（`template.json`）和来源文件名及 SHA-256 摘要（`metadata.json`）。多期数据保留每行的来源序号，关联订单保留商品行与主表行号。

桌面成品命名为 `BI-<报表类型>-<来源>-<标识>.onepagebi.html`。再次拖出相同成品会复用现有文件。如果现有副本已被编辑，新副本会带序号，避免覆盖。HTML 含交易明细，离线打开可筛选、切换语言并导出当前视图；历史中的 PNG 保留生成时的版本。

## 从源码运行

桌面外壳使用 WinForms + WebView2，界面使用 React / TypeScript，使用 SheetJS CE 和 csv-parse 读取表格，使用随软件打包的 SQLite（sql.js）执行整理。本地构建环境为 Windows x64、Node 24、pnpm 11。请在项目目录运行：

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm build:windows
.\release\OnePageBI.exe
```

首次桌面构建会下载固定版本的 WebView2 SDK 并校验 SHA-256。Windows 图形桌面及 Edge 可用时，运行 `pnpm test:windows` 进行桌面端测试。可用 `ONEPAGEBI_RELEASE` 指定要检查的解压版，用 `ONEPAGEBI_TEST_DIR` 指定隔离测试档案及截图目录。
